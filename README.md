# Язык предвыборной кампании — Кнессет 2026

Частотный анализ твитов лидеров израильских партий за период предвыборной
кампании. Цель — не политическая оценка, а сводка: какие слова и фразы они
используют, о чём говорят, кого упоминают, как меняется риторика по неделям.

**Окно кампании:** 17 июля 2026 (самороспуск Кнессета) → выборы 27 октября 2026.

---

## Быстрый старт (без реальных данных)

Проверить, что весь конвейер работает, можно за минуту — на синтетических
данных, до всякой возни с аккаунтами X:

```bash
pip install -r requirements.txt

python -m src.collect.make_sample      # ВЫДУМАННЫЕ твиты
python -m src.process.prepare --lemmatizer rules
python -m src.analyze.run
python -m src.report.build             # -> outputs/report.html
```

Отчёт на синтетике несёт красный баннер и не годится ни для публикации, ни для
пересылки: ни одна фраза в нём не является настоящей цитатой.

## Реальные данные

### 1. Доступ к X

X закрыл гостевой доступ, поэтому скрейпинг работает только через
залогиненную сессию. Два способа, достаточно одного.

**A. Cookies — надёжнее, пароль не нужен.** Парольный вход часто упирается в
капчу и подтверждение по почте; вход по cookies это обходит.

```
config/cookies/<username>.txt     # имя файла = логин X без @
auth_token=...; ct0=...           # оба обязательны
```

Взять их можно в DevTools браузера: F12 → Application → Cookies → `x.com`.
Подойдёт и JSON, и выгрузка расширения — `twscrape` понимает все три формата.

```bash
python -m src.collect.scrape cookies
```

**B. Пароль.**

```
config/accounts.txt
username:password:email:email_password
```

```bash
python -m src.collect.scrape login
```

Обе папки в `.gitignore`. Cookies — это полный доступ к аккаунту, ровно как
пароль: в репозиторий и в переписку они попадать не должны.

**Лучше отдельный аккаунт, не основной.** За скрейпинг X блокирует, и терять
рабочий аккаунт из-за сводки по частотности слов не стоит.

### 2. Проверить хэндлы

В `config/politicians.yaml` у всех стоит `verified: false` — хэндлы взяты
косвенно и требуют подтверждения. Скрипт проверит их существование:

```bash
python -m src.collect.scrape verify
```

Он напечатает найденные аккаунты с числом подписчиков и отдельно те, что
требуют внимания. Подтверждённым поставь `verified: true`, ненайденным —
исправь `handle` или оставь `null`.

У части политиков (Дери, Гафни, Гольдкнопф — религиозные партии) публичного
X-аккаунта, скорее всего, нет вовсе: их канал коммуникации — не твиттер.
Это само по себе результат, и в отчёте он виден как отсутствие строки.

### 3. Собрать и построить

```bash
python -m src.collect.scrape collect
python -m src.process.prepare          # stanza, ~400МБ при первом запуске
python -m src.analyze.run
python -m src.report.build
```

### Повторный сбор

`collect` **накапливает, а не перезаписывает**: результат сливается с уже
собранным и дедуплицируется по `tweet_id`. Запускать можно сколько угодно раз
по ходу кампании — до 27 октября это ещё много прогонов.

Почему именно так:

- неудачный или частичный прогон не затирает уже собранное;
- у существующих твитов обновляются лайки и просмотры — они растут со временем;
- твит, удалённый автором после прошлого сбора, остаётся в корпусе. Иначе
  выборка молча менялась бы задним числом, и цифры прошлой недели перестали бы
  воспроизводиться;
- запись атомарная (через `.tmp` + переименование), прерывание на середине не
  оставляет покалеченный файл.

Перед первым реальным сбором убедись, что в `data/raw/` не лежит синтетика:
у синтетических записей есть поле `_synthetic: true`, и `prepare` помечает
этим весь отчёт.

## Лемматизация иврита — почему без неё нельзя

`חטופים / החטופים / לחטופים / ולחטופים` — это одно слово в четырёх формах.
Без приведения к лемме частотный список превращается в мусор, а TF-IDF
размазывает сигнал по вариантам одного и того же слова.

Три бэкенда (`config/settings.yaml` → `analysis.lemmatizer`):

| Бэкенд | Качество | Цена |
|---|---|---|
| `stanza` | хорошее, по умолчанию | разовая загрузка модели ~400МБ |
| `dicta` | отличное | нужен интернет, запрос на каждый твит |
| `rules` | грубое | мгновенно, без зависимостей |

`rules` — эвристика на приставках, для отладки. Она режет корневые буквы
(`לימוד → ימוד`), поэтому под неё в `src/process/hebrew.py` заведён
защитный список `_NO_STRIP` для частотной политической лексики. Это снижает
ущерб, но не устраняет его: **для настоящей сводки нужен `stanza`.** Отчёт
показывает баннер, если построен на `rules`.

### Что stanza делает с текстом и как это учтено

Три её особенности ломают метрики, если ничего не предпринять:

1. **Местоимения сводятся к одной лемме:** `אנחנו`, `הם`, `אני` → `הוא`.
   Метрика «мы vs они» держится ровно на этом различии, поэтому у токенов
   с `upos == PRON` сохраняется поверхностная форма.
2. **Клитики и местоименные суффиксы отделяются:** `המחדל` → `ה` + `מחדל`,
   `אותם` → `את` + `ם`, `שלנו` → `של` + `נו`. Односимвольные клитики
   выбрасываются (`drop_noise`), а отделённые формы местоимений (`ם`, `ן`,
   `נו`) добавлены в лексиконы `we_words` / `they_words` — иначе полные
   формы не встретились бы в разобранном тексте ни разу.
3. **Пунктуация приходит отдельными токенами** и пролезает внутрь n-грамм
   (`מדינה . אנחנו`, `! ! התפטר`), разрывая настоящие фразы. Токены без
   букв и цифр отбрасываются; цифры сохраняются — `27 באוקטובר` осмысленно.

Из этого следует главное правило: **термы лексиконов прогоняются через тот же
лемматизатор, что и корпус** (`lemmatize_terms`). Лексиконы написаны со
слитным артиклем (`חוק הגיוס`, `משפחות החטופים`, `בית המשפט`), а stanza его
отделяет. Без общей нормализации темы молча обнулились бы при переходе с
`rules` на `stanza` — то есть именно при переходе к режиму «как надо».

## Что считается

| Метрика | Что показывает |
|---|---|
| Объём и темп | твитов в день, доля ретвитов/ответов, языки |
| N-граммы (1–4) | самые частые слова и фразы |
| **Keyness (G²)** | самые *отличительные* фразы — чем он отличается от остальных |
| Темы | доля твитов по 13 темам (безопасность, заложники, призыв, суд, …) |
| Риторика | атака vs программа, «мы» vs «они», лексика единства |
| Граф упоминаний | кто про кого — по @-хэндлам **и** по имени в тексте на иврите |
| Динамика | недельный объём, недельные темы, кто первым поднял тему |
| Стиль | восклицания, вопросы, эмодзи, длина, медиа, час публикации |
| Engagement | какие фразы дают лайки выше медианы (lift) |
| Повторяемость | самая частая 4-грамма и её доля — мантра или живой язык |

### Решения, которые влияют на цифры

- **Ретвиты исключены** из всех текстовых метрик. Ретвит — чужие слова;
  в ответе на «какие фразы использует ОН» им не место. В `overview` доля
  ретвитов сохранена как отдельная характеристика.
- **Keyness, а не просто частота.** «Израиль» частотен у всех и потому
  неинформативен. G² показывает, что человек говорит непропорционально часто
  на фоне остальных.
- **Медиана, а не среднее** в engagement: один виральный твит не должен
  определять оценку фразы.
- **Лексиконы не пересекаются.** Родовая оценочная лексика («провал»,
  «ответственность») вынесена в `rhetoric.attack` и убрана из тем — иначе
  тема «7 октября» завышалась втрое. Проверка на дубли термов между темами
  входит в правки конфига.
- **Второй твит, а не первый** при вычислении «кто первым поднял тему»:
  одиночное упоминание — случайность.
- **Часы приведены ко времени Израиля** (UTC+3, IDT — весь период кампании
  внутри летнего времени).

## Структура

```
config/
  settings.yaml       окно кампании, лимиты сбора, параметры анализа
  politicians.yaml    лидеры партий: хэндлы, партии, алиасы для графа
  topics.yaml         тематические и риторические лексиконы на иврите
  accounts.txt        аккаунты X (в .gitignore)
src/
  config.py           загрузка конфигов
  collect/scrape.py   login / verify / collect
  collect/make_sample.py  синтетика для проверки конвейера
  process/hebrew.py   чистка, определение языка, лемматизация (3 бэкенда)
  process/prepare.py  raw -> processed, кэширует леммы
  analyze/run.py      все метрики -> outputs/analysis.json
  report/build.py     -> outputs/report.html
data/raw/             *.jsonl по политику
data/processed/       tweets.jsonl + prepare_meta.json
outputs/              analysis.json, report.html
```

## Оговорки

- **Скрейпинг X противоречит его ToS.** Данные — публичные высказывания
  публичных лиц, но выбор способа сбора остаётся на тебе.
- Частотный анализ описывает **как часто прозвучало слово**, а не правоту
  говорящего и не искренность. Ирония, цитирование оппонента и отрицание
  («я никогда не говорил, что…») считаются как употребление.
- Лексиконы в `topics.yaml` собраны вручную и заведомо неполны. Их стоит
  дополнять по ходу кампании: новая тема появится — терминов для неё нет.
- Твиттер — не единственный и не главный канал израильской политики.
  Telegram и Facebook у многих активнее, а у религиозных партий X может
  отсутствовать вовсе. Выборка смещена в сторону тех, кто ведёт X.
